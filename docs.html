adytus Documentation

Private, encrypted AI workspace — use any model, keep your prompts yours.

adytus is a private AI workspace that lets you use ChatGPT, Claude, Gemini, and other AI models without leaking company data. Every prompt is encrypted client-side before it leaves your browser. adytus servers never see your plaintext — only you hold the key.

How it works

adytus sits between you and your AI provider. Here's the flow:

  1. You type a prompt — plain text, only inside your browser tab.
  2. adytus encrypts it — AES-256 encryption happens in the browser using your personal key before anything is sent anywhere.
  3. Encrypted prompt is relayed — your API key sends the encrypted prompt to your chosen AI provider (OpenAI, Anthropic, Google, etc.).
  4. Response comes back encrypted — adytus decrypts it locally in your browser so you can read it. Nothing readable ever touches our servers.
ℹ

Zero-knowledge architecture: adytus stores only ciphertext. Even if our servers were compromised, there is nothing readable to expose.

Getting started

Setup takes under two minutes. There's no software to install — adytus runs entirely in your browser.

Step 1 — Add your API key

adytus uses your own API key from your chosen AI provider. This means:

  • You're billed directly by the provider at their standard rates
  • adytus never pools or shares credentials
  • Your key is stored locally in your browser — never on our servers

To add a key, go to Settings → API Keys and paste your key from one of the supported providers:

ProviderWhere to get your key
OpenAI (GPT-4o, o1…)platform.openai.com → API Keys
Anthropic (Claude 3.5…)console.anthropic.com → API Keys
Google (Gemini 1.5…)aistudio.google.com → Get API key
xAI (Grok)console.x.ai → API Keys
OpenRouteropenrouter.ai → Keys
⚠

Keep your API key private. Anyone with your key can make requests billed to your account. adytus stores it encrypted in your browser's local storage and never transmits it to our servers.

Step 2 — Turn on encryption

Go to Settings → Privacy and toggle Encrypt prompts on.

When you enable encryption for the first time, adytus generates a unique AES-256 encryption key for you and prompts you to download it as adytus-key.json.

⚠

Save your key file. If you lose adytus-key.json, your encrypted conversation history cannot be recovered — not by you, not by adytus. Store it somewhere safe (password manager, encrypted drive).

Once encryption is on, the Encrypted badge appears in every chat session, confirming your prompts are protected.

Step 3 — Pick a model and start chatting

Use the model selector in the chat toolbar to choose your AI. The list is populated from the API keys you've added.

Chat normally — adytus handles encryption and routing transparently. Your conversation history is stored encrypted in our database, readable only by you.

Step 4 — Unlock on a new device

When you log into adytus on a new browser or device, your conversation history will appear locked. To unlock it:

  1. Go to Settings → Privacy
  2. Click Load encryption key
  3. Upload your adytus-key.json file

Your full history is immediately accessible. The key file is loaded into memory only — it's never re-uploaded to our servers.

File uploads

adytus supports uploading files directly into your chat context. Supported formats:

  • PDF — full text extraction with page awareness
  • Word documents (.docx) — paragraphs, tables, headings preserved
  • Plain text (.txt, .md, .csv) — sent as-is

Drag and drop a file into the chat window, or click the attachment icon in the input bar. File contents are included in the prompt context sent to the AI. Like all prompts, file contents are encrypted before leaving your browser.

ℹ

Large files are automatically chunked to fit within the model's context window. adytus uses the provider's token limits to determine chunk size.

Encryption deep-dive

adytus uses AES-256-GCM symmetric encryption, implemented via the browser's native Web Crypto API. No third-party crypto libraries are loaded.

The encryption flow per message:

  1. A random 96-bit IV (initialization vector) is generated for each message
  2. The plaintext prompt is encrypted with your AES-256 key + IV
  3. The IV is prepended to the ciphertext and stored alongside it
  4. The AI provider receives the encrypted payload via your API key
  5. The response is encrypted the same way before being stored

Your adytus-key.json file contains the raw key material exported from the Web Crypto API. It is never transmitted to adytus servers.

FAQ

Can adytus read my prompts?

No. With encryption enabled, adytus stores only ciphertext. We have no copy of your key and no technical ability to decrypt your conversations.

What happens if I lose my key file?

Your encrypted history becomes permanently inaccessible. We cannot recover it. This is intentional — it's the property that makes the zero-knowledge guarantee meaningful. Keep a backup in your password manager.

Is my API key safe?

Your API key is stored in your browser's local storage, encrypted with the same key you control. It is never sent to adytus servers. It goes only to the AI provider when you send a message.

Do you store conversation history?

We store encrypted conversation history so your chats are available across devices and sessions. The stored data is ciphertext only — readable only with your key.

Which plan includes encryption?

Encryption is available on all plans, including the free tier during beta.
